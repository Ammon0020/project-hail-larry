## Recent Fixes (2026-07-11)

- **Auth tiers: grace-period revocation + workspace registration gating** — Closes security audit finding 1.2. Destructive actions now have a grace period during which any connected device can cancel. **Device revocation:** `DELETE /api/devices/{id}` enters a pending state for `RevocationGracePeriodSeconds` (default 300 = 5 min); all connected devices see a `DeviceRevocationPending` broadcast event and can cancel via `POST /api/devices/cancel-revocation`. If unchallenged, the revocation executes when the timer fires. Grace period 0 = instant (backward compat). **Workspace registration:** `POST /api/workspaces` returns 403 by default (`allowRemoteWorkspaceRegistration: false` in config — use `app add-folder` on the host). When enabled, same grace-period flow with `WorkspaceRegistrationPending`/cancel events. New config fields: `AllowRemoteWorkspaceRegistration`, `RevocationGracePeriodSeconds`. New event types: `DeviceRevocationPending/Cancelled/Executed`, `WorkspaceRegistrationPending/Cancelled/Executed`. New API: `GET /api/pending-actions`, `POST /api/devices/cancel-revocation`, `POST /api/workspaces/cancel-registration`. 22 new tests across pairing, server, config, and daemon packages.
- **`app install-service` / `app uninstall-service`** — Cross-platform autostart registration. Linux: systemd user unit (`~/.config/systemd/user/local-agent.service`). macOS: launchd LaunchAgent (`~/Library/LaunchAgents/com.local-agent.plist`). Windows: HKCU Run registry key. All use `os.Executable()` for the binary path, refuse to silently overwrite existing installs, and include platform-specific tests for the generated file content.
- **Security audit + fixes (11 findings)** — Full backend security audit covering auth, path traversal, command injection, input validation, secrets, TLS, SQL injection, and DoS. 9 of 11 findings fixed; 2 deferred as design items in `docs/known-issues.md`. **Fixed:** (1) **HIGH — Loopback CSRF/WS exfil:** `sync.go` now checks the `Origin` header on WS upgrades and rejects cross-origin (set `InsecureSkipVerify: false`); `server.go` requires loopback mutating requests (POST/PUT/PATCH/DELETE) to have a loopback `Origin` header, blocking CSRF from malicious websites while keeping CLI (no Origin) working. (2) **Med — Events limit cap:** `parseEventParams` caps `?limit` at 10000. (3) **Med — Pairing rate limiting:** per-IP token bucket (5/min) on `/api/pair/*` endpoints via `golang.org/x/time/rate`, returns 429. (4) **Med — WS connection limit:** per-IP cap on concurrent WS connections. (5) **Med — ReadFile size limit:** `ReadFile` rejects files >50MB. (6) **Med — Event store retention:** `Prune(maxRows)`, `PruneOlderThan(maxAge)`, `StartPruneTicker` added; `PRAGMA auto_vacuum=INCREMENTAL`. (7) **Low — Symlink escape:** `safeJoin` now resolves symlinks via `EvalSymlinks` + `Lstat` and re-validates containment. (8) **Low — TLS insecure warning:** daemon logs loud warning if TLS is off and bound to 0.0.0.0. (9) **Low — Cert KeyUsage:** removed spurious `KeyEncipherment` (invalid for ECDSA) and unused `ClientAuth` ExtKeyUsage. **Deferred:** auth authorization tiers (any device can revoke others) and credentials-in-query-params (acceptable for LAN+TLS, WS ticket exchange is the future fix). All tests pass, `golangci-lint` clean.

- **Remote device auth (mobile "offline" + no files fix)** — The frontend stored the paired device credential (`lai:deviceCredential`) in localStorage but never sent it with API requests or the WebSocket handshake. On localhost, the backend's `isLoopback` check bypasses auth so everything worked. On a remote (LAN) device like a mobile phone, every REST call returned 401 and the WebSocket was refused — so the UI showed "offline" and no files loaded. Fix: `api.ts` now exports `getDeviceCredential()` and a `withAuthHeaders()` helper that reads the credential from localStorage and attaches `Authorization: Bearer <deviceId>:<secret>` to every `apiFetch` and direct `fetch` call (upload, export, MCP config). `useBackend.ts` `connectWebSocket` appends `deviceId`+`secret` query params to the WS URL (browsers can't set headers on WS handshakes; the backend's `sync.Hub.HandleWS` checks these for non-loopback connections). Credentials are read fresh on each connect/reconnect so a newly-paired device works without a reload. Pairing endpoints (`/api/pair/*`) are unaffected — they don't require auth and no credential exists yet at that point.
- **Codex harness "peer disconnected before response" fix** — The codex agent spec in `autodetect.go` listed `["codex-acp", "codex"]` as fallback commands. The bare `codex` CLI (`@openai/codex`) is an interactive TUI that requires a TTY on stdin — spawning it over pipes (as the ACP transport does) makes it exit immediately with "Error: stdin is not a terminal", causing the ACP Initialize handshake to fail with "peer disconnected before response". The `codex` CLI has no `acp` subcommand; ACP support is provided solely by the separate `@agentclientprotocol/codex-acp` npm package (installs the `codex-acp` binary). Removed the bare `codex` fallback so autodetect only registers the codex agent when `codex-acp` is installed. Added 3 tests in `autodetect_test.go`: (1) `TestCodexSpecExcludesBareTUI` — static regression guard that the spec never lists `codex`; (2) `TestCodexTUINotACPCompatible` — integration test (codex-installed-only) that spawns the bare TUI over pipes and verifies it exits with "stdin is not a terminal"; (3) `TestCodexAutodetectNoTUIFallback` — integration test (codex-installed-only) that verifies `Autodetect()` does not register a codex agent pointing at the TUI when `codex-acp` is absent.

## Recent Fixes (2026-06-30)

- **Permission prompt label hardening** — Some agents set a permission request's `ToolCall.Title` to an opaque tool-call ID (e.g. Claude `toolu_…`, OpenAI `call_…`, UUIDs, or random tokens like `muNNhDHjd`), which surfaced as "Permission Required / <id>". The previous heuristic only caught separator-free tokens and wrongly treated any `_`/`-` value as a real label. Now `looksLikeRawID` (backend `internal/acp/transport.go`, mirrored in frontend `ChatMessageItem.tsx`) recognizes ID-prefixed tokens, UUIDs, and long hex, falling back to a kind-derived label ("Run command", "Edit file", …). Covered by `TestLooksLikeRawID`.
- **Cross-platform test fix** — `TestExpandPathWindowsEnv` compared against `filepath.Join` (OS-dependent separator) and failed on Linux/macOS even though `expandWindowsEnv` only substitutes `%VAR%`. Expectation now uses the literal backslash path so it passes on all platforms.
- **Linux/macOS build script** — Added `build.sh` (counterpart to `build.ps1`): builds the frontend, re-embeds `internal/server/dist`, and compiles/installs the Go binary. Note: `internal/server/dist/` is gitignored, so a frontend build (`npm install && npm run build`) is required before `go build` can embed assets.

## Key Decisions

- Go module: `github.com/adama/local-agent`
- Frontend dir: `web/` (not `frontend/`)
- Dark theme default; Tailwind v4 `@theme inline` pattern
- Event-driven UI: all rendering derives from `AppEvent[]` stream
- SQLite via `modernc.org/sqlite` (pure-Go, no CGO)
- Must rebuild binary (`.\build.ps1`) after frontend changes — `go:embed` freezes frontend at compile time
- Note: `ACPClient.SendPrompt` signature change (adding `[]Attachment`) is a breaking change for out-of-tree implementers.
