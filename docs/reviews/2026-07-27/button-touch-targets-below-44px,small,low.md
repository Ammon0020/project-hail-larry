- name: Button touch targets fall below the 44×44px WCAG recommendation on mobile
- file: /media/adam/extex/projects/project-hail-larry/web/src/components/ui/button.tsx
- lines: 25-30
- description: The `size` variants produce heights of `h-8` (32px, `sm`), `h-9` (36px, `default` / `icon`), and `h-10` (40px, `lg`). WCAG 2.5.5 (Level AAA) and the more widely-cited mobile guidance recommend ≥44×44 CSS px for touch targets. This is a self-hosted web IDE that is explicitly designed for mobile (AGENTS.md: "On mobile, explorer, editor, chat, and settings are separate bottom-nav panels"), so the default button height of 36px is meaningfully undersized for finger taps, especially the `icon` variant (36×36) used throughout the chat tab bar, activity bar, and toolbars. Mis-taps on a 36px icon button next to another 36px icon button are common on phones. Consider raising `default`/`icon` to `h-10` (40px) or `h-11` (44px), and `sm` to `h-9`, on mobile breakpoints (e.g. `min-h-11 sm:h-9`) so desktop density is preserved while mobile gets safe targets. This is a low-severity but app-wide issue since nearly every interactive control is a `Button`.
- verification: Read the full file (59 lines). `size` variants on lines 25-30 set `h-9`/`h-8`/`h-10`/`size-9`. None approach 44px. AGENTS.md confirms mobile is a first-class target with bottom-nav panels, so sub-44px targets are a real UX regression on the primary mobile surface.
